## Priority Issues

**[P1] The corner menu panel overlaps and clips the home-screen wordmark.**
- **Why it matters**: Confirmed directly in a screenshot — opening the menu from the splash renders the dropdown panel on top of "Guess my animal," clipping the text mid-word. This is the very first thing a first-time visitor sees if they explore the menu before searching, on a product whose "considered, not decorated" identity depends on exactly this kind of collision never happening.
- **Fix**: Either give `.menu-panel` a higher `z-index`-aware backdrop/shadow so the overlap reads as intentional layering rather than a collision, or reposition the `.home` content (or cap `.menu-panel`'s width/position) so the panel never overlaps the wordmark at any viewport width. The cleanest fix is probably nudging the wordmark's top margin down slightly on `.home` specifically when the panel can plausibly reach it, or capping the panel width so it doesn't extend as far left.
- **Suggested command**: `/impeccable polish`

**[P1] Quick Answers — the product's actual reason for existing — has no internal chunking at 8 unbroken rows.**
- **Why it matters**: The one thing someone opens this app for (e.g. "is it dangerous?") sits in an undifferentiated 8-row list with no visual distinction between the safety-relevant cluster (What is it / Carnivore / Dangerous) and the trivia cluster (Awake when / Hibernates / Pet / Domesticated / Eaten). This directly works against the product's own "an answer in about four seconds" promise — you have to scan the whole list every time, not jump to the one row that matters.
- **Fix**: A subtle rule or spacing break after the third row, or promote the highest-stakes/most-asked questions (Dangerous, Carnivore) so they cluster first with a visible gap before the behavioural rows.
- **Suggested command**: `/impeccable distill`

**[P2] At a Glance can wrap to 3+ chip rows with zero grouping, despite the code itself calling it secondary.**
- **Why it matters**: On Wolf alone, 8 chips wrap across multiple lines at mobile width, given equal visual weight (same card, same styling) as Quick Answers — even though app.js's own comment describes this section as "nice to have, nobody scans for first." The hierarchy the code intends isn't visible on screen.
- **Fix**: Visually subordinate it — smaller chip padding/font, tighter gap, or a hard cap with a "show more" — so it reads as the "at a glance" aside it's named for, not a second full answer list.
- **Suggested command**: `/impeccable typeset`

**[P2] No loading affordance during the ~1.5s Wikipedia fetch.**
- **Why it matters**: The photo card shows a static, unmoving fallback emoji while the real photo loads — for someone glancing at their phone mid-conversation (the product's own stated context), an unmoving "empty" state for over a second reads ambiguously as "no photo exists" rather than "still loading," undermining exactly the confidence the four-second promise is selling.
- **Fix**: A subtle pulse/shimmer on `.pcard-fallback` while a fetch is genuinely in flight, distinct from the true resting no-photo state.
- **Suggested command**: `/impeccable delight`

**[P2] Desktop leaves an unexplained ~290px dead zone between the search box and the corner menu.**
- **Why it matters**: Confirmed visually — the search unit is deliberately centered within the same 588px column as the feed (per DESIGN.md's own layout rule), while the menu button stays pinned to the physical viewport corner (also a deliberate, documented choice — "the same place on the splash and on an animal"). Both decisions are individually correct, but together they read as an unintentional layout bug rather than two considered rules, because nothing visually explains why the gap exists.
- **Fix**: This is a genuine tension between two documented rules, not a simple bug — needs a decision, not just an edit. Options: extend a subtle visual connector (rule line, matching background) between the two, or accept the gap explicitly by widening the topbar's effective width band.
- **Suggested command**: `/impeccable layout`

**[P3] Report-send failure offers a low floor of reassurance.**
- **Why it matters**: "That did not send. Please try again in a moment" is the entire recovery path — no retry button, no confirmation that the typed message is still there (it is, confirmed in app.js — the field isn't cleared on failure — but nothing tells the user that).
- **Fix**: A one-line reassurance ("your message is still here") or auto-focusing Send so retry reads as obviously one tap away.
- **Suggested command**: `/impeccable clarify`

## Minor Observations

- The `.dice` shuffle button's 180° rotate on click has no accompanying scale/bounce — reads slightly flatter than how confidently everything else in the system commits to its motion.
- "Found in" glance chip shows multi-region species as one long comma-run inside a single pill (fine at 2-3 regions, risks a very long pill for wider-range species).
- The report textarea's placeholder ("The photo shows a different animal…") doesn't change when a different "kind" radio is selected, despite the dialog already knowing which one is checked — a small missed opportunity given how much other context-awareness already exists in that form.
- Share panel's brand icons (WhatsApp/X/Facebook) are the only saturated non-Sun colour on the page — technically outside the "no second accent" rule but justified as literal brand marks; worth a one-line note in DESIGN.md's Do's and Don'ts if not already implicitly covered.

## Questions to Consider

2. The photo card's one authored animation fires identically whether a real photo loaded or the emoji fallback is standing in for "we don't have one." Should a genuinely missing photo get its own quieter arrival, so the one dramatic beat in the system is reserved for when a real photo actually lands?
3. The corner menu and the centered content column are each individually well-reasoned — is the fix here really "adjust the layout," or does the desktop experience need its own compositional idea, not a mobile layout with two independently-justified rules that happen to leave a gap between them?
