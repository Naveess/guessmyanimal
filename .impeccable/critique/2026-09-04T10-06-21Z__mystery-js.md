## Design Specificity Verdict

Partially authored, partially reskinned. Result card and mode tabs correctly extend
existing system precedent (the result card's color-mix tint is the exact
One-Yellow-Rule recipe; tabs reuse the theme toggle's segmented control near-verbatim).
Filter chips (solid ink fill, inverted text) and the hint photo (plain object-fit:cover
tile) invent new visual languages instead of reusing patterns DESIGN.md already
documents (the report dialog's tinted kind-chip; the signature Photo Card component).

Deterministic scan (detect.mjs --json index.html, exit 2): one finding, a
broken-image warning on #mysteryPhotoImg's empty src — confirmed false positive,
the container stays hidden the whole time src is empty. Live/rendered detector
agreed, reported clean.

Additional finding from browser evidence, not caught by the design review: direct
navigation to ?mystery=1 (the exact URL the new Daily share panel distributes)
renders duplicated header chrome — the home search bar floats above the Mystery
Animal topbar. Root cause: openMystery() never calls dock(), and routeFromURL()'s
direct-URL path skips goHome() (the only function that docks #searchunit) entirely.
Every recipient of a shared Daily result link hits this.

## Overall Impression

Mechanics are sound, copy voice is right. Components with direct system precedent
to reuse (tabs, result card) did; components without one (chips, photo) improvised
instead of reusing the pattern behind the precedent. Combined with a real
chrome-duplication bug on the exact URL the new sharing feature distributes, the
biggest opportunity is tightening the loop between what got built and what this
system already knows how to do.

## What's Working

1. Result card tint — color-mix(sun 16%, card) is the exact One-Yellow-Rule recipe used elsewhere.
2. Mode tabs — near-verbatim reuse of the theme toggle's segmented control.
3. Typo tolerance + tone — one-edit-distance matching and lines like "That's the one — streak reset" extend the product's forgiving voice convincingly into a competitive context.

## Priority Issues

[P0] Direct/shared ?mystery=1 links render duplicated, broken-looking header chrome
Why it matters: this is the exact URL the new Daily share panel distributes — every
shared-link recipient hits visibly broken chrome before seeing a hint.
Fix: call dock()/equivalent for #searchunit in openMystery(), including the
direct-URL path in routeFromURL() that currently skips goHome() entirely.
Suggested command: /impeccable harden

[P0] Keyboard focus ring is stripped from the guess input
Why it matters: #mysteryGuess:focus{outline:none} overrides the site-wide
:focus-visible rule every other input leaves alone — a keyboard/switch-access
player gets no visible indicator on the one control the screen is built around.
Fix: drop outline:none, let the global :focus-visible rule apply.
Suggested command: /impeccable audit

[P1] Filter-chip active state invents a new visual language
Why it matters: a solid ink fill with inverted text is the strongest
"generic trivia app" tell on the page, and creates two loud fills on one screen
where the system's rule is one.
Fix: swap to the report dialog's proven kind-chip tint recipe.
Suggested command: /impeccable polish

[P1] Daily give-up is one unconfirmed tap with a 24-hour cost
Why it matters: visually identical to the low-stakes Endless give-up, no
distinction between the two stakes.
Fix: add a lightweight confirm specifically on the Daily path.
Suggested command: /impeccable harden

[P2] The hint photo abandons the site's signature Photo Card component
Why it matters: DESIGN.md calls the Photo Card the product's one authored visual
moment; the hint photo is a plain cropped tile with no name overlay, no entrance
animation, on the highest-visibility new surface.
Fix: reuse the actual Photo Card component, heavily blurred, revealing per hint.
Suggested command: /impeccable polish

## Persona Red Flags

Jordan (first-timer): lands on Daily facing three "0" stat tiles with no copy
explaining what Daily is or that it's shared across players; nothing visually
announces "same product as the yellow splash."

Sam (accessibility-dependent): hits the P0 focus-ring bug directly on the screen's
one core control. aria-pressed used correctly elsewhere — it's specifically this
CSS override that breaks the visual signal.

Casey (distracted-mobile, the product's own stated primary context): most exposed
to both P1s — a stray tap on Give-up during Daily burns the whole day with no
confirmation, and Share panel overlap obscures the result they meant to share.

## Minor Observations

- Share panel opens upward and overlaps/truncates the Daily result at 420x900.
- No loading affordance while the Wikipedia photo fetch is in flight.
- The milestone toast's fire emoji is the only UI-chrome emoji outside the documented per-animal fallback system.
- .mystery-tab and .theme-btn are near-duplicate CSS blocks worth consolidating.
- Long animal names aren't exercised in any captured screenshot; no truncation rule on .mystery-result-name.
